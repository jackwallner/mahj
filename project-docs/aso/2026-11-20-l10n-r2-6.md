# Localized metadata, round 2 batch r2-6, 2026-11-20

Five locales rewritten field by field: or-IN (Odia), pa-IN (Punjabi), ta-IN (Tamil), te-IN (Telugu), ur-PK (Urdu). Name, subtitle, keywords, promotional text and description changed in each. Every locale here is thin evidence, see below.

## Where these locales are indexed (Apple table, fetched 2026-11-20)

- India (IND): English (U.K.), Bangla, Gujarati, Hindi, Kannada, Malayalam, Marathi, Odia, Punjabi, Tamil, Telugu, Urdu. So or-IN, pa-IN, ta-IN, te-IN and ur-PK share one keyword pool in India with hi, bn-BD, gu-IN, kn-IN, ml-IN, mr-IN (other batches) and en-GB.
- Pakistan (PAK): English (U.K.) and Urdu. ur-PK plus en-GB is the whole local pool.
- The app is live in both storefronts (iTunes lookup returns it in `in` and `pk`). US share is 96% of proceeds, so none of these five is a US field; the US-indexed overlap rule does not apply.
- The Search API ranked us in India for terms that exist only in en-US (`mahjong flashcards` 7, `mahjong drills` 13, `mahjong tutor` 5), so en-US words count in India even though Apple's table does not list en-US there. All Latin keywords below avoid en-US and en-GB tokens (name, subtitle, keywords).

## Design for the five

- Name: `Mahj Trainer: Mahjong <learn>` in the language's imperative or "let us learn" form. The Latin word `Mahjong` is deliberate: it lets every Latin keyword combine with `mahjong` inside the same locale, and it is how readers type it. The name check (iTunes search, in and pk) found no other app with the exact name.
- Subtitle: native script, `American mahjong` plus `rules` (and `practice` where it fits in 30 characters). Charleston is left out of the subtitle because en-GB already carries it in Latin.
- Keywords: Latin tokens are split across the five so none repeats inside the shared India pool or against en-US/en-GB; the rest is native-script learning vocabulary (beginner, lesson, quiz, strategy, tips, card, tile, free, game, test, guide, course). Old keywords were transliterations of tile names (dot, bam, crak, dragon, wind, flower, joker, rack, hand, pung); no evidence for any of them, and English tile words are already in en-US.
- Description: faithful to the live en-US text (rooms, Play a Hand, Mahj Minute, free vs Mahj+, disclaimer), one short statement that the in-app text is English, and the in-app English names kept in Latin (Play a Hand, Endless Practice, Fix My Mistakes, Game Night Prep, Timed Challenge, Master Tables, Mahj Minute, How to Play) so a reader can find them. Room headings carry the native name plus the English one in brackets. The old text was the pre-1.3 translation (Thursday intro, no English-UI note, "Master Tables" and "Play a Hand" only partly there). Settings path is given with the English word in brackets because iOS UI language varies.

## Validation

A whole-token check across the five locales and en-US/en-GB found no repeats.

## Unsure, for the reviewer

- No native review. I wrote the Odia, Punjabi, Tamil, Telugu and Urdu copy myself. Spots to check: Odia `କକ୍ଷ` for room, `ସଦସ୍ୟତା` for subscription, `ଆଧିକାରିକ` for official; Punjabi `ਅਧਿਕਾਰਤ`, `ਅਸੀਮਤ`, `ਕਮਰਾ`; Tamil `கற்போம்` in the name and `திருப்பங்கள்` for turns; Telugu `నేర్చుకో` (informal, chosen to fit 30) and `రెన్యూ`; Urdu `باریاں` for turns, `مستند` for official, and bidi when Latin feature names sit inside Urdu sentences.
- The Latin `Mahjong` inside each name is a judgment call: it trades some native look for keyword combination. If a native reviewer dislikes it, the native transliteration of the old names is a safe fallback, but it matched zero queries in the Search API.
- The India pool is shared with hi, bn-BD, gu-IN, kn-IN, ml-IN, mr-IN, rewritten by other runs. If those runs also put Latin tokens such as `guide`, `tips` or `course` in their fields, those tokens would repeat in the India pool and waste budget; nobody can check that until the runs are merged.
- Thin evidence throughout: no autocomplete in five languages, no popularity data. The Latin gap terms are the only measured part, and I rank them by result-set size, not by search volume.
