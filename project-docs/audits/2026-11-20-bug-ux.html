The purchase path, the frozen trial flow, restore and the membership checks held up under four passes, and every bug found is low severity. B4

lowconfirmeddata
Impact

Not reachable today: every field added since release is optional, so every shipped shape still decodes. It is a trap for the next data change, where it would hit every player at once, on the app that earns two thirds of the fleet's proceeds. lowplausibleentitlement
Impact

How it happens
  1. A monthly or yearly member opens the app, so the stored membership snapshot says active and renewing.

B11

In zones where the clocks change at midnight (Lebanon, Egypt, Chile, Azores), the streak is one day off after the change

lowconfirmedstate
Impact

A player in Lebanon, Egypt, Chile, the Azores or any zone whose daylight saving change skips local midnight gets a streak that is one too low from the day after the change, or one too high if they skip that day. Once a year, small count error, no data lost.

How it happens
  1. Set the phone time zone to Beirut (Lebanon moves its clock from 00:00 to 01:00 on the last Sunday of March; Egypt, Chile and the Azores do the same on other dates).
  2. On Sunday 28 March 2027 (the change day) finish one drill in the evening. The stored last active day is the start of that day, which is 01:00 because 00:00 does not exist.
  3. On Monday 29 March finish a drill. The code counts whole days from 01:00 Sunday to 00:00 Monday, which is 23 hours, so it reads 0 days and leaves the streak where it was.
  4. Alternative: practise Sunday, skip Monday, practise Tuesday. The gap reads 1 day (47 hours), so the streak grows although Monday was missed.
Where
Shared/Services/ProgressStore.swift:111Shared/Services/ProgressStore.swift:97Shared/Services/TrialOfferPacer.swift:79
Suggested fix

Compare day keys (year, month, day from the calendar) or use Calendar.dateComponents on the two dates' day components instead of startOfDay differences, for the streak, currentStreak and isSessionPaced.

Evidence
let lastDay = calendar.startOfDay(for: last)
let gap = calendar.dateComponents([.day], from: lastDay, to: today).day ?? 0
if gap == 1 {
    streakCount += 1
} else if gap > 1 {
    streakCount = 1
} // gap == 0: same day, streak unchanged

startOfDay on a day with no midnight returns 01:00. Day components between 01:00 on one day and 00:00 on the next are 0 because only 23 hours pass. The stored value is a Date, not a day key, so the same shift also reaches currentStreak (ProgressStore.swift:97) and the install-day pacing in TrialOfferPacer.isSessionPaced (TrialOfferPacer.swift:79), which would call install day plus 2 still session paced in the same case.

Checked by: ProofTimeStateTests/testStreakCountsEveryDayAcrossDstInOddZones, run repo-mbpro328ff-1120-102109-32348: FAILED. Asia/Beirut day 38 (2027-03-29 23:30 local): streakCount 37, expected 38; every later day was one short (526 failed assertions, all Beirut). New_York, Havana, Lord_Howe, Kiritimati, Apia and Kolkata grew on every one of 300 days.

Not proven: Run 1 proved Asia/Beirut only. Africa/Cairo, America/Santiago and Atlantic/Azores are in the second run (see gh_sim). America/Havana did not fail in run 1 (its streak grew on every day), so Cuba is not affected on the tested dates.
